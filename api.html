API Reference¶

Core¶

class polkupy.Ride(data: DataFrame, ride_id: str | None = None, bike_id: str | None = None)[source]¶

A single ride.

The class includes the points of one track plus its metadata. Rides are the building block of all processing methods, built on top of a pandas.DataFrame. The minimum required columns are:

  • time: timezone-aware timestamp

  • lat: latitude in degrees

  • lon: longitude in degrees

Optional but highly recommended are:

  • bike_id: an identifier for the bicycle used

  • ride_id: an identifier for the ride itself

Any other data or metadata is optional and simply carried along on data untouched.

Methods that transform the data return a new Ride rather than mutating in place, so they can be chained, e.g. ride.localized().with_speed().smoothed(). The underlying DataFrame is always available as data.

property distance_km: float¶

Total distance covered in km.

Calculated as the cumulative great-circle distance between consecutive points.

property duration: Timedelta¶

Elapsed wall-clock time from start_time to end_time.

The output is a pandas.Timedelta. This is total elapsed time, not moving time. It includes any time spent stopped (e.g. at traffic lights).

property end_time: Timestamp¶

The timestamp of the last point, as a pandas.Timestamp.

Raises:

IndexError – If data has no points.

class polkupy.Trips(data: DataFrame)[source]¶

A collection of rides.

The class is backed by one pandas.DataFrame and grouped by ride_id.

Iterating yields Ride objects; methods that filter or transform the collection return a new Trips so they can be chained.

Clock¶

Time-of-day alignment shared across polkupy.

polkupy.clock.add_time_of_day(df: DataFrame, tz: str = 'Europe/Berlin') → DataFrame[source]¶

Align every ride to a shared 24h clock, ignoring the calendar date.

Rides recorded on different days become directly comparable: a ride that started at 08:00 and one that started at 08:05 can be replayed side by side. Adds ride_start_s (seconds since local midnight the ride started) and virtual_s (ride_start_s plus elapsed time into the ride).

Parameters:

  • df (pandas.DataFrame) – Points with ride_id, time columns, e.g. Trips.data.

  • tz (str) – IANA timezone name used to resolve local time of day.

Returns:

Copy of df with ride_start_s and virtual_s columns added.

Return type:

pandas.DataFrame

polkupy.io.gpx.load_gpx(filepath: str, extensions: list[str] | None = None) → DataFrame[source]¶

Load a GPX file and extract data into a pandas.DataFrame.

latitude and longitude are mandatory GPX attributes, so gpxpy raises GPXException while parsing if either is missing. time is optional in the GPX schema, so gpxpy does not validate it. However, it is required by Ride, so it is explicity checked and raises ValueError if absent. A requested extension that is not found in the file raises a UserWarning, since the data is still usable without the extension.

Parameters:

  • filepath (str) – Path to the GPX file.

  • extensions (list[str], optional) – Extensions of the GPX file to read, e.g. heart rate data.

Returns:

A DataFrame containing the GPX data with columns for time, latitude, longitude, and optionally elevation and other specified extensions.

Return type:

pandas.DataFrame

Raises:

  • ValueError – If the file has no track points, a point has no timestamp, or a point’s latitude, longitude, or elevation is outside a physically plausible range.

  • gpxpy.gpx.GPXException – If the file is missing a mandatory GPX field (latitude or longitude).

Synthetic Data¶

Generate synthetic ride data, e.g. for test fixtures or documentation examples.

polkupy.synthetic.generate_track(waypoints: Sequence[tuple[float, float]], *, start: str | Timestamp = '2026-01-01T08:00:00Z', speed_kmh: float = 20.0, sample_rate_s: float = 5.0, elevation_m: float | Sequence[float] | None = None, gps_noise_m: float = 0.0, elevation_noise_m: float = 0.0, speed_noise_kmh: float = 0.0, seed: int | None = None) → DataFrame[source]¶

Generate a synthetic ride by interpolating between waypoints at constant speed.

This is a straight-line (“as the crow flies”) interpolation between consecutive waypoints, not a road-following route - useful for test fixtures and documentation examples where a plausible-looking, GPS-shaped track is needed without real ride data (which could contain personal information).

Parameters:

  • waypoints (Sequence[tuple[float, float]]) – (lat, lon) points the track passes through, in order. Must contain at least 2.

  • start (str | pandas.Timestamp) – Timestamp of the first point. If no timezone is provided, then treated as UTC.

  • speed_kmh (float) – Constant speed used to convert the waypoints’ total distance into elapsed time. Must be positive.

  • sample_rate_s (float) – Interval between generated points, in seconds. Must be positive.

  • elevation_m (float | Sequence[float], optional) – Either a single value broadcast to all waypoints, or a sequence of elevations, in metres. Defaults to None, which omits the ele column.

  • gps_noise_m (float, optional) – Standard deviation of gaussian noise added to each point’s position, in metres, simulating GPS jitter. Defaults to 0.0 (no noise).

  • elevation_noise_m (float, optional) – Standard deviation of gaussian noise added to each point’s elevation, in metres. Only applied if elevation_m is given. Defaults to 0.0 (no noise).

  • speed_noise_kmh (float, optional) – Standard deviation of gaussian noise added around speed_kmh to produce a reported speed_kmh column, simulating a device’s own speed sensor. Defaults to 0.0, which omits the speed_kmh column.

  • seed (int, optional) – Seed for the random noise generator, for reproducible output. Defaults to None (nondeterministic).

Returns:

Points with time, lat, lon columns (plus ele/speed_kmh if elevation_m/speed_noise_kmh are given). Identical in shape to what Ride expects.

Return type:

pandas.DataFrame

Raises:

ValueError – If fewer than 2 waypoints are given, or speed_kmh or sample_rate_s is not positive.
